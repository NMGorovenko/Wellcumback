# 0.10 — подключение друзей из приложения

## Пользовательский путь

Ведущий выбирает «Создать игру» → «Через интернет» или «Локальная сеть». Приложение поднимает сервер комнат; для интернета поднимает временный туннель. Появляется строка подключения с адресом, версией протокола и кодом комнаты. Друг вставляет её в своё приложение на Windows или Mac. Доступ ведущего хранится отдельно. Создатель выбирает любую из трёх историй, всем приходят одинаковые переходы и последствия действий. Пауза доступна каждому, продолжение и смена истории — ведущему.

Туннель не требует собственного VPS, но адрес живёт пока работает приложение и поставщик не гарантирует доступность. При невозможности подключения показать причину, возможность повторить или указать постоянный сервер. Отдельный пакет VPS должен иметь документированный запуск, TLS, ограничение запросов и корректную остановку. Покупка VPS не нужна для начала реализации.

## Архитектура

- Сохранить хозяина комнаты единственным автором симуляции и существующую подтверждаемую очередь ввода/эпохи. Расширить протокол на clean/moving и поднять версию.
- Вынести транспорт запроса: прежний HTTP для совместимости сайта; WebSocket с частыми обменами для приложений и пользовательского сервера.
- Один серверный обработчик правил для D1 и SQLite на Node. WebSocket-сервер работает из Electron или отдельного процесса VPS. Токены не печатаются в логах и не входят в приглашение.
- Electron остаётся sandboxed/context-isolated. Узкий preload мост запускает/останавливает собственный сервер и передаёт только сообщения игрового протокола. Никакого доступа renderer к Node, shell, произвольным файлам или IPC.
- Город, экран, казарма, переезд используют общий жизненный цикл сетевой комнаты. Каждый компьютер имеет первый набор управления; он переводится в фиксированное место. В переезде третий участник — Никита помогает Ярику и Насте. В казарме безымянный солдат не становится Ромой.
- Добавить V8 как самостоятельную модель оборотов/передач и граф Web Audio. Не использовать чужие записи без лицензии. Условия mute/паузы/потери фокуса одинаковы для всех клиентов.
- FPS измеряет завершённые кадры Three.js; общий небольшой индикатор и сохраняемая настройка без второго render loop.

## Проверки перед выпуском

1. Миграция настроек, FPS 30/60/144 Hz и отсутствие измерений при выключенном индикаторе.
2. V8: плавные обороты, смена передач, ограниченные хлопки, отсутствие утечек/клиппинга; реальный рендер звука и прослушивание доступным способом.
   После обратной связи: заметно тише прежнего варианта, без высокочастотного писка на максималке. Тест использует настоящий разгон `tickCity`, три отдельных спада оборотов и ровное движение на четвёртой. Первый переход происходит примерно через 0,7 секунды; верхний диапазон выше 2 кГц подавлен и проверяется OfflineAudioContext. Для прослушивания сохраняется `outputs/audio/Mustang-V8.wav`.
3. Валидация подключения, несовместимые версии, неверные приглашения, ограничения запросов и полномочий, завершение сервера/туннеля.
4. Настоящие независимые клиенты сервера: подключение 2–3 участников, роли, переходы всех историй, короткие нажатия, пауза, переподключение, отсутствие повторных наград.
5. Полные механики казармы/переезда после JSON-снимка и совместный перенос/уборка. Длительный след не превышает предел снимка и не теряет грязь.
6. Проверить WebSocket через реальный временный интернет-адрес, а также локальный прямой сервер. Не называть это проверкой двух физических сетей, если устройства не доступны.
7. Сборка сайта, автономного HTML, приложений Mac/Windows, пакет VPS. Настоящий запуск на доступном Mac; контрольные суммы всех файлов выпуска, исходники и документы, отдельный тег. Ограничения Windows/Intel/физических геймпадов отмечать честно.
