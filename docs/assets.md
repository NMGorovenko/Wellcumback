# Исходные материалы и игровые ассеты

Пользовательские оригиналы сохраняются в `references/` без обрезки, перекодирования и потери качества. Код моделей, анимаций, звука и сценарии — такие же исходники проекта. `public/` содержит копии и производные изображения, которые загружает браузер.

Комнатные фотографии перенесены из другой задачи по просьбе пользователя. Повторное фото сохранено как прислано. EXIF-ориентация оригиналов остаётся неизменной: при просмотре и создании производных нужно учитывать поворот, а не перезаписывать исходник. `manifest.json` содержит 27 изображений после добавления фотографий переезда; индекс комнаты — отдельный Markdown-файл. Добавляя новые оригиналы, нужно обновлять и манифест.

Фотографии отражают планировку первой игры: экран и тумба, диван напротив, кухня/бар слева, рабочее место и окно справа. Их используют как опору для моделирования. Они не выдаются за автоматический 3D-скан комнаты; размеры и свободные проходы адаптированы под игровой экран. Подробности: [комната](room.md).

Референс казармы используется для процедурной геометрии пяти помещений, дверей, отделки и поста. Скриншот стульев сохраняет исходный визуальный дефект как материал для проверки контактов. Оба новых файла внесены в манифест с размером и SHA-256; ранее присланные фотографии остаются без изменений.

## Изображения, загружаемые игрой

- `public/characters/faces/roma.png`, `yaroslav.jpg`, `nikita.jpg` — выбранные фотографии для лиц. Кадрирование выполняется UV-координатами в `components/game/world/rig.ts`, а не обрезкой исходного файла. Области описаны в [персонажах](characters.md).
- `public/characters/roma-v1.png`, `yaroslav-v1.png` — сохранённые портреты ранней генерации; запросы находятся в [истории промптов](image-prompts.md).
- `public/characters/nikita-reference.jpg` — сохранённый портрет Никиты для карточки персонажа.
- `public/materials/apartment-oak-v1.png` — используемая текстура дуба квартиры; в переносимой сборке она встроена вместе с тремя фото лиц.

Во второй истории фотография используется только у Ромы: он помогает рядом с безымянным солдатом, затем убирает. Все остальные армейские персонажи анонимные, с процедурными лицами. В соло активен один уборщик — Рома. Никиты и Ярика в казарме нет; сохранённые исходники их лиц остаются для других историй.

Файлы из `public/` доступны браузеру как игровые ресурсы и входят в веб-сборку. Поэтому выбранные фотографии лиц не являются исключительно локальными материалами. Остальные оригиналы из `references/` автоматически не публикуются.

## Воспроизводимые модели и звук

| Исходник | Что создаётся |
| --- | --- |
| `components/game/world/apartment.ts` | Стены, пол, кухня, барные стулья, диван, тумба, стол и кресло |
| `components/game/world/rig.ts` | Тела, головы, причёски, одежда, искривлённая сетка фото-лица и конечности |
| `components/game/screen/screen-model.ts` | Рамка, полотно, спицы, пружины и зацепы экрана |
| `components/game/screen/drill-props.ts`, `lib/game/screen/staging.ts` | Стулья и опорные точки, дрель, пылесос/шланг, кирпичная пыль и её след на белой стене |
| `components/game/clean/environment-v3.ts` | Пять комнат и коридор, дверные проёмы, кремовые стены, деревянный пост с красной накладкой и телефоном, стенды и шкаф химзащиты |
| `components/game/clean/props-v3.ts` | Туалет, душ, стиралка с отдельным барабаном и дверцей, брюки, капли и следы |
| `components/game/clean/actors-v3.ts` | Анонимные персонажи, бригада в химзащите, швабры и пакет со штанами |
| `components/game/world/render-kit.ts`, `labels.ts` | Общие примитивы, материалы и генерируемые текстуры надписей |
| `lib/game/audio/clean-foley.ts` | Локальный синтез звуков второй истории через Web Audio |

Стиль PS3 получается из фототекстур, упрощённых объёмных форм, материалов и анимаций. Отдельных скрытых Blender/FBX/GLB-исходников у этих процедурных моделей нет: воспроизводимый исходник — TypeScript. Текстура плитки, инструкции на стендах, таблички и текстовые облачка реплик генерируются при создании сцены. Переупорядочивание игровых ролей не меняет исходные фотографии и UV-области лиц. Следы казармы строятся из фактических объектов движка и отмываются вместе с ними. Звук не требует загруженных сэмплов или сетевого голосового сервиса.

## Полный архив для переноса

Оригиналы `references/` сохранены в Git вместе с кодом. `outputs/`, зависимости и каталоги сборки исключены из Git; готовые игровые файлы прикладываются к GitHub Releases. Для отдельной полной резервной копии предусмотрен скрипт:

```sh
python3 scripts/archive-source.py outputs/friendslop-source.zip
```

Запускать из папки проекта после сохранения актуальных файлов. Нужны Python 3 и Git; в Windows команда интерпретатора может называться `python`.

Скрипт берёт отслеживаемые и неигнорируемые новые файлы Git, а затем отдельно добавляет всё содержимое `references/`. В архив попадают код, `public/`, `GOAL.md`, документация, конфигурация проекта, lock-файл и фотоисходники. `node_modules`, `.git`, `dist`, `.wrangler`, `outputs` и файлы `.env` исключаются; пример `.env.example` допускается. Оригиналы записываются байт в байт.

Внутри создаётся каталог `friendslop/` и `SOURCE-MANIFEST.json` со списком упакованных файлов, размерами и SHA-256. После записи скрипт выполняет проверку целостности ZIP и сообщает путь, число файлов и размер. Этот манифест относится ко всему архиву; `references/manifest.json` описывает отдельно исходные изображения.

Для восстановления распаковать архив, сохранить `references/` вместе с кодом, выполнить `npm ci` и `npm run dev -- --port 3001`. Контрольные суммы позволяют сверить перенос каждого файла. Созданный архив содержит оригинальные фото — передавать его как полную копию проекта, учитывая это содержимое.

Обычная публикация игры использует ресурсы из `public/` и не требует размещения исходного ZIP в интернете. Сам факт существования скрипта не означает, что финальный архив уже собран и проверен для текущей версии; это отдельный шаг выпуска.

## Переносимый выпуск 0.3.0

Игровой артефакт остаётся `FRIENDSLOP.html` с встроенными кодом, стилями, лицами и текстурой дерева. Новые процедурные предметы, пыль, комнаты и надписи не требуют внешних файлов или сетевой загрузки. Игровой ZIP содержит HTML, инструкцию и BUILD-INFO.json; полный source ZIP дополнительно включает все 22 исходных изображения и документацию. Сборка, хеши и публикация проверяются владельцем выпуска перед заполнением окончательных [заметок 0.3.0](releases/v0.3.0.md).

## Следующие материалы

Для будущей истории Mustang сохранены оба ракурса, но сценарий и механика ещё не определены. Фотографии нужны для кузова, пропорций и характерных фонарей. Номер автомобиля и посторонние люди не нужны для игрового образа. Новые фото друзей или комнаты добавляются в `references/`, а используемые игрой производные и UV-настройки обновляются отдельно.
