# Совместная игра 0.11.2

Поддержаны город, «Экран на полстены», казарма и переезд, 2–3 компьютера. Участники используют одинаковую версию игры и одно приглашение. На каждом устройстве работают WASD/E/Q/Shift или стандартный геймпад; не требуется выбирать раскладку второго персонажа.

## Пригласить друга

В приложении Mac/Windows открыть «Онлайн-комната», выбрать имя, число мест и «Создать игру». «Локальная сеть» подходит для одной сети; «Через интернет» пробует временный туннель. После успешного создания комнаты появляется строка `WCB1:…` и кнопка копирования. Друг вставляет всю строку в поле подключения своего приложения. Хозяин оставляет игру открытой. После закрытия сервера приглашение перестаёт работать.

VPS необязателен. Временный туннель зависит от доступности Cloudflare в обеих сетях. На текущем подключении адрес выдаётся, но TLS-соединение с узлом обрывается: проверка не прошла, игра показывает ошибку вместо нерабочего приглашения. LAN проверен. В режиме «Одна сеть / VPN» приложение показывает текущие IPv4-адреса интерфейсов. Если их несколько, выберите адрес общей сети; единственный доступный адрес выбирается автоматически. Сервер слушает выбранный интерфейс, приглашение содержит этот же адрес. Если сеть отключилась, запуск с её адресом отклоняется без закрытия действующей комнаты. Для постоянного `wss://` адреса подготовлен [отдельный серверный пакет](server.md).

Для Tailscale поддержан диапазон `100.64.0.0/10`, наряду с домашними `10/8`, `172.16/12` и `192.168/16`. Это диапазон адреса, а не автоматическое подтверждение VPN: оба компьютера должны быть доступны друг другу в одной виртуальной сети, её правила должны разрешать соединение игры. Одинаковый VPN для выхода в интернет не гарантирует связь устройств. [Адреса Tailscale](https://tailscale.com/docs/concepts/tailscale-ip-addresses), [доступ между устройствами](https://tailscale.com/docs/how-to/connect-to-devices).

Веб-версия сохраняет комнаты через `/api/rooms` с кодом из восьми символов и умеет подключаться к серверу по приглашению. Права доступа к сайту не меняются: код комнаты не даёт доступ к закрытому сайту. Отдельный `.html` рассчитан на игру за одним компьютером; для сетевого режима нужна настольная или веб-версия.

## Роли и переходы

Создатель комнаты начинает ведущим. «Передать ведущего» в списке участников меняет только его основную роль с ролью выбранного помощника. Машина, выбор историй и право продолжить после паузы переходят новому ведущему. Третий участник остаётся на своей роли. Персонажи, их положения, инструменты, сумки и прогресс не пересоздаются. Передача сначала сохраняется на паузе; новый ведущий продолжает вручную.

| Сцена         | Основная роль                                   | Первый помощник      | Второй помощник |
| ------------- | ----------------------------------------------- | -------------------- | --------------- |
| Город / экран | Водитель / Никита                               | Ярик                 | Рома            |
| Казарма       | Безымянный солдат → другой сослуживец на уборке | Рома всё прохождение | Безымянный боец |
| Переезд       | Ярик                                            | Настя                | Никита          |

В казарме нет Никиты и Ярика. Рома не изображает виновника. В одиночной казарме Рома сначала стоит рядом как свидетель, а после инцидента один занимается уборкой.

Паузу запрашивает любой участник. Продолжение, смена этапа, перезапуск и возвращение в город доступны текущему ведущему. Присоединение нового игрока возможно в городе или на инструктаже. Возвращение прежнего игрока возможно посреди любой истории.

## Потеря связи и возвращение

При разрыве связи игра ждёт на паузе. Даже быстрое переподключение между двумя ответами сервера не теряется: сервер хранит запрос паузы, пока приложение создателя не сохранит остановленный мир. После возвращения все отпускают кнопки и стики; ведущий нажимает «Продолжить». Старые команды не выполняются, таймеры не догоняют пропущенное время.

Обновление той же вкладки восстанавливает подключение автоматически. После закрытия вкладки или гостевого приложения откройте «Онлайн» → «Вернуться в комнату». Эта кнопка использует личное сохранённое подключение; обычное приглашение не выдаёт чужую роль. Данные возврата остаются только на этом устройстве и не входят в приглашение. Явный выход из комнаты удаляет сохранённое подключение.

Если аварийно закрылся сам интернет-туннель, сервер сохраняет комнату на паузе. В приложении создателя появится «Онлайн → Восстановить интернет-связь». После успешного восстановления скопируйте обновлённое приглашение: адрес может поменяться. Гость вставляет его в «Онлайн → Обновить приглашение → Вернуться по новому приглашению». Используется прежний личный токен, без нового вступления и смены роли. После закрытия гостевого приложения сначала нажмите «Вернуться в комнату», затем обновите приглашение. Повторная неудача восстановления не удаляет прохождение. Не закрывайте комнату ради смены адреса; это завершает сеанс.

Комната не истекает, пока хотя бы один участник остаётся на связи. После ухода всех сервер хранит её ещё шесть часов. Приложение **создателя** должно оставаться открытым даже после передачи ведущего: там продолжается симуляция и, для настольного режима, работает сервер. Передача роли не переносит процесс сервера. Закрытие создателем комнаты завершает сеанс; отключение компьютера с локальным сервером не покрывается восстановлением сетевого соединения.

Сетевая попытка имеет стабильный `attempt`: передача ведущего и переподключение не создают повторное начисление результата. Только новое прохождение или тренировочный эпизод меняют попытку.

## Устройство протокола

Версия протокола 5. Приложение создателя рассчитывает мир фиксированными шагами 60 Гц. Гости отправляют последовательные кадры ввода; сервер хранит их до cumulative ACK. Нажатие и отпускание между снимками не теряются. Старые эпохи, просроченный ввод и команды с чужими полномочиями отбрасываются; продолжение требует нейтрального ввода. Гость принимает снимок ведущего, не запускает конкурирующую симуляцию.

Общие серверные правила используются в Cloudflare D1 и локальном Node SQLite. Прямой transport — WebSocket, прежний веб-transport — HTTP. Срок неактивной комнаты — 6 часов с последнего принятого запроса участника. Токены участников хешируются; приглашение содержит ключ доступа к relay, но не личный токен ведущего. URL валидируется: публичный сервер требует WSS, WS разрешён для настоящих локальных IP/localhost. Размер снимка ограничен 96 КиБ, сообщения и частота запросов ограничены отдельно.

Для длинной казармы максимум 180 следов: близкие старые следы одного вида объединяются с сохранением массы грязи и уже сделанной уборки. Новая пена остаётся пеной и появляется у стиралки.

Проверки: серверные полномочия/очереди/эпохи, адаптеры всех историй, настоящие WebSocket-клиенты и отдельный гостевой процесс через sandboxed Electron preload. Предыдущая приёмка веб-комнат сохранена в [отчёте 0.7](acceptance-v0.7.0.md). Две физические сети и совместная пара Windows/Mac пока не проверены.
