# Архитектура и выбор движка

## Решение на первый прототип

TypeScript + React для оболочки, Three.js для первой 3D-истории, Canvas 2D для короткой второй истории. Проект запускается в современном настольном браузере на macOS/Windows. Внешний сервис для игры не нужен: сервер отдаёт приложение, состояние партии и счёт остаются на устройстве.

Это решение для компактного подарочного сборника с быстрыми изменениями по фотографиям и рассказам. Не утверждаем, что оно оптимально для любой будущей версии.

## Unity или веб

| Критерий                                            | Текущий веб-прототип                                                                   | Unity                                                                                         |
| --------------------------------------------------- | -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| Запустить у друзей                                  | Ссылка или локальный сервер                                                            | Сборка приложения; веб-экспорт тоже возможен                                                  |
| Быстрые изменения меню и историй                    | Удобно через React и TypeScript                                                        | Потребуется UI и сцены Unity                                                                  |
| Небольшие 2D/3D мини-игры                           | Достаточно текущей архитектуры                                                         | Также подходит                                                                                |
| Реалистичная физика мебели и ткани                  | Сейчас игровые приближения; для роста подключить Rapier после выбора конкретной задачи | Редактор, физические компоненты и развитый игровой инструментарий удобнее для такого масштаба |
| Риг персонажей, анимационные графы, постановка сцен | GLB-модели и Three AnimationMixer; редактор отдельный                                  | Сильная сторона Unity                                                                         |
| Поддержка и сложность                               | Не строить собственный универсальный движок                                            | Не вводить отдельный движок только ради меню и пары механик                                   |

**Когда пересмотреть решение:** сложные физические взаимодействия становятся основой большинства игр, нужен редактор для самостоятельной сборки уровней, много анимированных персонажей и постановочных сцен, обязательные нативные сборки с игровыми сервисами. Тогда выбрать Unity до изготовления большого числа финальных ассетов. Перенос правил с TS на C# всё равно будет работой, не обещать автоматическую миграцию.

Three.js — библиотека 3D, а не готовый игровой движок. Поэтому состояния, победа, очки и действия описаны отдельно от сцены. React не рассчитывает физику в рендерах. Для простого 2D-прототипа Canvas достаточен; Phaser имеет смысл при росте количества 2D-сцен, анимаций, коллизий и карт. Пока добавлять второй игровой фреймворк без такой потребности не нужно.

Источники, проверенные при выборе:

- [Three.js: Making a Game](https://threejs.org/manual/en/game.html)
- [Three.js: Fundamentals](https://threejs.org/manual/en/fundamentals.html)
- [Unity: Web browser compatibility](https://docs.unity3d.com/6000.0/Documentation/Manual/webgl-browsercompatibility.html)

## Структура

- `app/page.tsx` — оболочка: выбор историй, бригада, результаты.
- `components/game/screen/` — 3D-сцена и интерфейс истории про экран.
- `components/game/clean/` — Canvas-сцена и интерфейс казармы.
- `lib/game/screen/engine.ts` — автомат состояний экрана, очки, натяжка, баланс, высоты и зацепление.
- `lib/game/clean/engine.ts` — движение, последовательность станций, уборка, таймер и результат.
- `lib/game/presets.ts` — люди, палитра комнаты и реестр историй.
- `lib/game/types.ts` — общий контракт результата.
- `lib/game/webmcp.ts` — необязательный запуск истории через поддерживаемый браузером WebMCP.
- `hooks/use-game-loop.ts` — один игровой цикл, клавиатура, пауза при потере фокуса, снятие обработчиков.
- `components/ui/` — компоненты интерфейса из стартового набора; не смешивать с игровыми правилами.
- `public/characters/` — используемые в игре портреты.
- `references/` — локальные исходные фото, исключены из Git и публикации.
- `tests/` — автоматические проверки механик без браузера.
- `docs/scenarios.md` — живые сценарии и граница между реализованным и задуманным.

## Правила изменения

1. Сначала менять правила в движке соответствующей истории и проверять переходы. Рендереры читают состояние, а не решают, когда победа.
2. Общие вещи выносить после появления двух применений. Не создавать универсальную ECS или редактор заранее.
3. Не добавлять логику игр в React-разметку: там только команды, отображение и lifecycle.
4. Дельта ограничена 50 мс, чтобы возвращение из фоновой вкладки не прокручивало игру. Потеря фокуса включает паузу и очищает клавиши.
5. React получает до 30 снимков в секунду; Three.js и Canvas читают состояние по ref. Ресурсы GPU, ResizeObserver и обработчики очищаются при размонтировании.
6. Клавиши задаются `KeyboardEvent.code`, поэтому русская раскладка не мешает WASD.
7. Счёт сохраняется один раз при завершении; повторный запуск создаёт новую попытку.
8. Константы пресетов заменять отдельно от правил. Личность героя не должна быть привязана к цвету или индексу в механике.

## Ограничения текущей сборки

- Один компьютер и одна клавиатура. Сетевой кооператив и геймпады ещё не реализованы. На некоторых клавиатурах возможен hardware key rollover при многих одновременно зажатых клавишах.
- Условная процедурная графика; персональные портреты не являются готовыми риггированными 3D-моделями.
- Баланс стульев и натяжка — игровые модели; симуляции ткани и rigid-body физики нет.
- Нативные macOS/Windows-приложения ещё не собраны; браузерный запуск не равен проверке на всех устройствах.
- Нет сохранения незавершённой партии, звук пока короткими сигналами в первой истории. Во второй пока нет звукового оформления.
- UI крупнее и адаптируется к узкому экрану, есть экранные кнопки первого игрока. Основной режим — настольная клавиатура; мобильный кооператив не заявлен.
- API WebMCP опционален. Контекст браузера для проверки регистрации не доступен в текущей автоматической проверке; его поддержка не заявлена как проверенная. Кнопки и клавиатура работают независимо от него.

## Проверки

`npm test` проверяет полное прохождение первой истории, последовательность второй, натяжку и восстановление после ошибки, падение и потерю прогресса сверления, сохранение высот, действие третьего игрока, паузу, таймаут и сверхурочную уборку. `npm run typecheck` проверяет TypeScript. `npm run build` собирает production-версию.

После существенного визуального изменения полезно отдельно провести ручной игровой тест в браузере: камера и читаемость, одновременные клавиши, переключение историй, повторный старт и сохранение счёта. Автоматические проверки движка не подменяют эту проверку.

Линтер проверяет собственный код проекта. Неизменённые компоненты стартового UI-набора и его `use-mobile.ts` исключены из lint-прохода, поскольку поставляемый набор содержит собственные несовместимости с агрессивными правилами стартового конфига. TypeScript-проверка охватывает и их. Для динамических canvas-сцен сохранён корректный `role="img"`, несмотря на общее правило предпочитать `<img>`.
